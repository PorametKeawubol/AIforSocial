# KruSim (ครูซิม) — ห้องเรียนจำลองสำหรับฝึกครู
### โครงการประกวด JUMP THAILAND HACKATHON: AI for the Future of Thai Education

> *"นักบินมี Flight Simulator, ศัลยแพทย์มี Surgery Simulator... แล้วทำไมครูไทยต้องขึ้นสอนจริงตั้งแต่วันแรก?"*

---

## 1. ที่มาและปัญหา (Problem Statement)

นักศึกษาครุศาสตร์/ศึกษาศาสตร์ทั่วประเทศต้องออกฝึกประสบการณ์วิชาชีพ (ฝึกสอน) โดยแทบไม่เคยมีโอกาส "ยืนสอนหน้าห้องจริง" มาก่อน ปัญหาที่ตามมาคือ

- **ไม่มีพื้นที่ให้ผิดพลาด** — ความผิดพลาดครั้งแรกของครูฝึกสอน เกิดขึ้นกับเด็กจริง ส่งผลต่อการเรียนรู้ของเด็กจริง
- **ขาดโอกาสฝึกรับมือสถานการณ์หลากหลาย** — เด็กหลังห้อง เด็กถามคำถามยาก เด็กเรียนรู้ช้า ห้องเรียนคุมไม่อยู่ สิ่งเหล่านี้ฝึกจากตำราไม่ได้
- **Feedback ช้าและจำกัด** — อาจารย์นิเทศเข้าสังเกตการสอนได้เพียงไม่กี่ครั้งต่อเทอม ครูฝึกสอนส่วนใหญ่จึงไม่รู้จุดอ่อนของตัวเอง
- **ความเหลื่อมล้ำระหว่างสถาบัน** — มหาวิทยาลัยขนาดใหญ่มีโรงเรียนสาธิตให้ฝึก แต่สถาบันขนาดเล็ก/ต่างจังหวัดไม่มีทรัพยากรเทียบเท่า

**ครูคืออาชีพที่มีความเสี่ยงสูงต่ออนาคตของคนอื่น แต่กลับมีเครื่องมือฝึกซ้อมน้อยที่สุด**

---

## 2. แนวคิดหลัก (Core Concept)

**KruSim** คือแพลตฟอร์ม "ห้องเรียนจำลอง" ที่ให้นักศึกษาครูและครูใหม่ ฝึกสอนกับ **นักเรียน AI (Simulated Students)** ที่มีบุคลิก พฤติกรรม และระดับความเข้าใจแตกต่างกันเหมือนห้องเรียนจริง

### จุดต่างที่สำคัญที่สุด: "นักเรียน AI ไม่ได้แกล้งเข้าใจ"
ระบบไม่ได้เป็นเพียง roleplay — นักเรียน AI แต่ละคนมี **Knowledge State** ของตัวเอง มันจะ "เข้าใจ" ก็ต่อเมื่อครูอธิบายได้ชัดเจนจริง

- สอนงง → เด็ก AI ถามกลับ, เข้าใจผิด, ทำข้อสอบผิด
- สอนข้ามขั้น → เด็ก AI ตามไม่ทัน และแสดงออกแบบเด็กจริง (เงียบ, เดาสุ่ม, ถอดใจ)
- สอนดี → เด็ก AI ตอบคำถามได้ อธิบายกลับได้ด้วยภาษาของตัวเอง

หลักการนี้อิงจาก **Feynman Technique / Learning by Teaching**: การวัดว่าใครเข้าใจอะไร วัดได้ดีที่สุดจากการให้เขาอธิบายกลับ — ในที่นี้ "คะแนนของเด็ก AI คือกระจกสะท้อนคุณภาพการสอนของครู"

## 3. WHAT / HOW / WHO

### 📌 WHAT — ผลิตภัณฑ์คืออะไร
แพลตฟอร์มเว็บ (รองรับมือถือ) ประกอบด้วย 3 ส่วนหลัก

1. **Classroom Simulator (2.5D Visual Classroom)** — ไม่ใช่หน้าจอแชท แต่เป็น **ภาพห้องเรียนมุมมองจากหน้าชั้น (สายตาครู)** มีนักเรียน AI 4–8 คนนั่งประจำโต๊ะเรียงเป็นแถว แต่ละคนมีอนิเมชันตามสถานะภายใน: ยกมือถาม หันไปคุยกัน ฟุบหลับ พยักหน้า ทำหน้างง — ครูต้อง "อ่านห้อง" จากภาพเหมือนยืนสอนจริง สอนผ่านเสียง พิมพ์ หรืออัปโหลดสไลด์ เด็กพูดผ่านเสียง TTS + speech bubble
2. **Live Interaction Engine** — นักเรียน AI ยกมือถาม แทรกสถานการณ์ (เด็กคุยกัน เด็กหลับ เด็กถามนอกเรื่อง) แบบเรียลไทม์
3. **Reflection & Coaching Report** — จบคาบ ระบบสรุปว่าเด็กแต่ละคนเข้าใจอะไร เข้าใจผิดตรงไหน พร้อม AI Coach ให้ feedback การสอน

### ⚙️ HOW — ทำงานอย่างไร

**ขั้นตอนการใช้งาน (User Flow)**
1. ครูเลือก/สร้างบทเรียน กำหนดจุดประสงค์การเรียนรู้ (Learning Objectives)
2. เลือกโปรไฟล์ห้องเรียน เช่น ม.ต้นโรงเรียนขยายโอกาส, ห้อง gifted, ห้องเรียนรวม (มีเด็ก LD)
3. เริ่มสอน — นักเรียน AI โต้ตอบตาม persona และ knowledge state ของแต่ละคน
4. ระหว่างสอนมี "เหตุการณ์สุ่ม" (Random Events) ให้ฝึกแก้สถานการณ์
5. จบคาบ → นักเรียน AI ทำ quiz หรืออธิบายเนื้อหากลับ → ระบบคำนวณ "คะแนนความเข้าใจของห้อง"
6. รับรายงาน: จุดแข็ง จุดที่อธิบายข้าม การกระจายคำถาม จังหวะการสอน พร้อมคำแนะนำเพื่อสอนรอบถัดไป

**สถาปัตยกรรมเทคนิค (Technical Architecture)**
- **Multi-Agent System** — นักเรียน AI แต่ละคน = 1 agent มี persona prompt + memory + knowledge state แยกกัน
- **Knowledge State Tracker** — ติดตามว่า agent แต่ละตัว "ได้รับ" เนื้อหาอะไรจากคำสอนของครูบ้าง โดยเทียบกับ learning objectives
- **Orchestrator** — ตัวกลางจัดคิวว่าเด็กคนไหนจะถาม/แสดงพฤติกรรมเมื่อไร เพื่อให้ห้องเรียนดูมีชีวิต ไม่ใช่ตอบพร้อมกันหมด
- **Visual Rendering Layer (2.5D)** — ฉากห้องเรียน + avatar เด็กพร้อมอนิเมชันตามสถานะของ agent (เข้าใจ/งง/เบื่อ/อยากถาม) ทำด้วย Vue + CSS animation หรือ PixiJS — สถานะภายในของ agent ขับเคลื่อนภาพบนจอโดยตรง (Roadmap อนาคต: ห้องเรียน 3D และวิดีโอ AI-generated)
- **Evaluation Engine** — LLM-as-judge ประเมินความเข้าใจของเด็ก AI + คุณภาพการสอนของครู โดยอิงเกณฑ์มาตรฐานสากล (ดูหัวข้อ "มาตรฐานอ้างอิง")
- **Stack ที่เสนอ**: Frontend Vue.js / Backend C# ASP.NET Core หรือ Node.js + Claude/GPT API + WebSocket สำหรับ real-time

### 🎯 WHO — เพื่อใคร

| กลุ่มเป้าหมาย | ปัญหาที่แก้ | ช่องทาง |
|---|---|---|
| **นักศึกษาครุศาสตร์** (กลุ่มหลัก) | ไม่มีที่ฝึกก่อนออกฝึกสอนจริง | B2B ผ่านคณะครุศาสตร์ทั่วประเทศ |
| **ครูบรรจุใหม่ / ครูผู้ช่วย** | ขาด mentor และ feedback | สพฐ. / เขตพื้นที่การศึกษา |
| **ครูอาสา, ครู กศน., ติวเตอร์** | ไม่มีพื้นฐานวิชาชีพครู | B2C สมัครใช้เอง |
| **อาจารย์นิเทศ** | สังเกตการสอนได้จำกัด | ใช้รายงานจากระบบประกอบการนิเทศ |

## 4. ฟีเจอร์เด่น (Key Features)

1. **Student Personas หลากหลาย** — เด็กเก่งขี้เบื่อ, เด็กหลังห้อง, เด็กขี้อาย, เด็กช่างถาม, เด็ก LD/สมาธิสั้น, เด็กที่บ้านมีปัญหา (ปรับแต่ง/สุ่มได้)
2. **Comprehension-Based Scoring** — คะแนนไม่ได้มาจากการ "เล่นตามบท" แต่มาจากความเข้าใจจริงของเด็ก AI
3. **Random Classroom Events** — ฝึก classroom management เช่น เด็กทะเลาะกัน ไฟดับ เด็กถามคำถามที่ครูตอบไม่ได้
4. **AI Coach อิงเกณฑ์สากล** — feedback รายคาบแสดงเป็น **radar chart 3 แฉกตามโดเมน CLASS** (Emotional Support / Classroom Organization / Instructional Support) + คำแนะนำรายข้อตาม Rosenshine's Principles + กราฟพัฒนาการระยะยาว
5. **Scenario Library** — คลังสถานการณ์ที่อาจารย์นิเทศ/สถาบันสร้างเพิ่มและแชร์กันได้
6. **โหมดสอบรับรอง (KruSim Certificate)** — การสอบสอนมาตรฐานแบบสมัครใจ ตามโมเดล TOEIC (ดูหัวข้อ 6)

## 5. ความสอดคล้องกับวัตถุประสงค์การแข่งขัน

| วัตถุประสงค์ JUMP THAILAND | KruSim ตอบโจทย์อย่างไร |
|---|---|
| ส่งเสริมนวัตกรรมต่อยอดเชิงพาณิชย์ | โมเดล B2B ชัดเจน: ขาย license ให้คณะครุศาสตร์ ~60+ สถาบัน และหน่วยงานอบรมครูของรัฐ |
| สร้างอนาคตการศึกษาให้ "ผู้เรียนหรือผู้สอน" ทั่วถึงเท่าเทียม | ยกระดับ **ผู้สอน** เป็นทางออกที่ scale ที่สุด — ครูดี 1 คนส่งผลต่อเด็กหลายพันคนตลอดอาชีพ ลดช่องว่างระหว่างสถาบันที่มี/ไม่มีโรงเรียนสาธิต และเปิด **สนามสอบที่เท่ากันทั่วประเทศ** ผ่านการสอบออนไลน์ + ศูนย์สอบในพื้นที่ห่างไกล |
| สร้างเครือข่ายนิสิต–เอกชน–รัฐ | ต้องทำงานร่วมกับคณะครุศาสตร์ (สถาบัน), สพฐ./คุรุสภา (รัฐ), และผู้ให้บริการ AI/EdTech (เอกชน) โดยธรรมชาติของโปรเจกต์ |

## 6. ระบบสอบรับรอง — KruSim Certificate ("TOEIC ของวิชาชีพครู")

### หลักคิด: ไม่เพิ่มภาระครูเด็ดขาด
ครูไทยแบกภาระการประเมินมากอยู่แล้ว (ว.PA, เอกสารประเมิน, ชั่วโมง PLC) — KruSim จึงออกแบบตาม **โมเดล TOEIC** ไม่ใช่การประเมินภาคบังคับตัวใหม่:

- **สมัครใจ 100%** — ไม่มีใครถูกบังคับสอบ แรงจูงใจมาจากประโยชน์ของคะแนน ไม่ใช่คำสั่ง
- **สอบเมื่อพร้อม สอบซ้ำได้** — ผลสอบไม่ดีไม่มีผลลบ ไม่ติดประวัติ
- **คะแนนเป็นทรัพย์สินของผู้สอบ** — ใช้ยื่นสมัครฝึกสอน เตรียมสอบบรรจุ สมัครงานโรงเรียนเอกชน/ติวเตอร์

### แยก "ยิม" ออกจาก "สนามสอบ"
- **โหมดฝึก (ยิม)** — ใช้ฟรี ไม่เก็บคะแนนถาวร ไม่มีใครเห็น ซ้อมพังกี่รอบก็ได้ — ความรู้สึก "ปลอดภัยที่จะผิดพลาด" คือหัวใจของการเรียนรู้
- **โหมดสอบ (สนามสอบ)** — อีเวนต์แยกที่เลือกเข้าเอง ทุกคนสอบกับห้องเรียน AI ชุดเดียวกัน (persona เดิม, misconception เดิม, เหตุการณ์แทรกเดิม) → คะแนน CLASS 3 โดเมนที่เทียบกันได้ทั่วประเทศ — กรรมการสอบสัมภาษณ์แต่ละสนามให้คะแนนไม่เท่ากัน แต่ห้องเรียนจำลองให้เงื่อนไขเหมือนกัน 100%

### สองช่องทางเข้าถึง (ลดความเหลื่อมล้ำ)
- **สอบออนไลน์** — สำหรับผู้มีอุปกรณ์และอินเทอร์เน็ต สอบจากที่ไหนก็ได้ ลดต้นทุนเดินทาง
- **ศูนย์สอบ** — สำหรับพื้นที่ห่างไกล ใช้โครงสร้างที่มีอยู่แล้ว: มหาวิทยาลัยราชภัฏ (มีทุกภูมิภาค), ศูนย์ กศน., โรงเรียนประจำอำเภอ — สร้างเครือข่ายรัฐ–สถาบันไปในตัว

### ลดภาระเดิม ไม่ใช่เพิ่มของใหม่
เจรจากับคณะครุศาสตร์ให้รายงานจากระบบนับแทนเอกสารบางส่วนที่นักศึกษาต้องเขียนส่งอาจารย์นิเทศอยู่แล้ว (เช่น บันทึกสะท้อนการสอน) → ใช้ KruSim แล้วงานเอกสาร **ลดลง**

### แนวทางการรับรอง (Positioning)
ระยะแรก: "ใบรับรองทักษะเสริม" ที่คณะครุศาสตร์ใช้ประกอบการประเมินฝึกสอน → ระยะยาว: เสนอความร่วมมือกับคุรุสภา (ไม่เคลมว่าแทนการสอบครูผู้ช่วยตั้งแต่วันแรก)

> **ประโยคสรุป:** *"KruSim ไม่ใช่การประเมินครูเพิ่มอีกตัว — มันคือยิมที่ฝึกฟรี และสนามสอบที่เข้าเมื่ออยากได้ใบเบิกทาง เหมือน TOEIC ของวิชาชีพครู"*

## 7. โมเดลธุรกิจ (Business Model)

- **B2B (หลัก)** — License รายปีสำหรับคณะครุศาสตร์/ศึกษาศาสตร์ คิดตามจำนวนนักศึกษา
- **B2G** — โครงการอบรมครูบรรจุใหม่ร่วมกับ สพฐ. / เขตพื้นที่ / คุรุสภา
- **B2C** — Subscription รายเดือนสำหรับติวเตอร์และผู้เตรียมสอบครูผู้ช่วย
- **Freemium** — โหมดฝึกใช้ฟรี (จำกัดจำนวนคาบ/เดือน) เพื่อสร้างฐานผู้ใช้
- **ค่าธรรมเนียมสอบ (โมเดล TOEIC)** — รายได้ต่อครั้งสอบจาก KruSim Certificate โดยมีทุน/โควตาฟรีสำหรับผู้ขาดแคลนผ่านศูนย์สอบ

## 8. ขอบเขต MVP สำหรับ Hackathon

**สิ่งที่ต้องเดโม่ให้ได้ (Must Have)**
- **ฉากห้องเรียน 2.5D** — เด็ก AI 3–4 คนนั่งประจำโต๊ะ มีอนิเมชันพื้นฐาน (ยกมือ, ทำหน้างง, ฟุบ) ไม่ใช่หน้าจอแชท
- สอน 1 บทเรียนสั้น (แนะนำ: เศษส่วน ป.5 — มี misconception จากงานวิจัยให้ใช้) ผ่านเสียง/พิมพ์
- นักเรียน AI ถามแทรกตามความเข้าใจจริง
- จบคาบ: เด็ก AI ทำ quiz + รายงานสรุปความเข้าใจรายคน + feedback จาก AI Coach

**Nice to Have (ถ้ามีเวลา)**
- Voice input/output ให้เหมือนสอนจริง
- Random event 1–2 เหตุการณ์
- กราฟเปรียบเทียบการสอนรอบที่ 1 vs รอบที่ 2 (โชว์ว่าครูพัฒนาได้จริง — ทรงพลังมากตอนเดโม่)

**บทเดโม่ที่แนะนำ**: สอนแบบ "แย่" ให้กรรมการดู 1 รอบ (เด็ก AI งง ทำข้อสอบตก) แล้วสอนแบบ "ดี" อีกรอบ (คะแนนห้องพุ่ง) — เห็น cause & effect ใน 3 นาที

---

## 9. จุดขายตอน Pitch (Key Messages)

1. **เปิดด้วยปัญหา**: "ความผิดพลาดครั้งแรกของครูทุกคน เกิดขึ้นกับเด็กจริงเสมอ"
2. **เปรียบเทียบ**: นักบินมี Flight Sim, หมอมี Surgery Sim — ครูไทยไม่มีอะไรเลย
3. **จุดต่างเทคนิค**: ไม่ใช่ chatbot roleplay แต่เป็นห้องเรียนภาพจริงที่เด็ก AI "เข้าใจจริงเมื่อถูกสอนดี" — วัดผลได้เป็นตัวเลขตามเกณฑ์สากล (CLASS, Rosenshine)
4. **ไม่เพิ่มภาระครู**: โมเดล TOEIC — ยิมฝึกฟรี + สนามสอบสมัครใจ ผลสอบเป็นใบเบิกทาง ไม่ใช่การประเมินภาคบังคับ
5. **ความเท่าเทียม**: "เด็กครุศาสตร์ที่ยะลากับที่กรุงเทพ ควรมีสนามฝึกและสนามสอบที่เท่ากัน" — สอบออนไลน์ + ศูนย์สอบทั่วประเทศ
6. **Impact ที่ scale**: พัฒนาครู 1 คน = พัฒนาเด็กหลายพันคนตลอดอาชีพครู
7. **เล่าจากประสบการณ์จริง**: ผู้พัฒนามีประสบการณ์เป็น TA และดูแลระบบการเรียนการสอน (Moodle) เข้าใจ pain point ทั้งฝั่งผู้สอนและระบบ

## 10. ความเสี่ยงและคำตอบที่เตรียมไว้ (Q&A Prep)

| คำถามที่กรรมการอาจถาม | คำตอบ |
|---|---|
| AI จะเหมือนเด็กจริงแค่ไหน? | ไม่ต้องเหมือน 100% — เป้าหมายคือฝึก "ทักษะการอธิบายและรับมือ" เหมือน flight sim ที่ไม่ใช่เครื่องบินจริงแต่ฝึกนักบินได้จริง |
| ต่างจาก ChatGPT ยังไง? | Multi-agent + knowledge state tracking + ห้องเรียนภาพ 2.5D + การประเมินตามเกณฑ์สากล — ChatGPT ทำ roleplay ได้ แต่ไม่มีระบบวัดผลว่า "สอนดีขึ้นหรือยัง" |
| จะเพิ่มภาระครูไหม? | ตรงกันข้าม — โหมดฝึกสมัครใจและเป็นส่วนตัว การสอบเป็นทางเลือกแบบ TOEIC และรายงานจากระบบใช้แทนเอกสารสะท้อนการสอนบางส่วนได้ → งานเอกสารลดลง |
| เกณฑ์คะแนนมาจากไหน ใครกำหนด? | อิงมาตรฐานสากลทุกชั้น: CLASS 3 โดเมนเป็นแกนคะแนน + Rosenshine's Principles เป็นคำแนะนำ + Bloom's Taxonomy ออกแบบ quiz — ไม่ใช่ AI ตั้งเกณฑ์เอง |
| ใครรับรองผลสอบ? | ระยะแรกเป็นใบรับรองทักษะเสริมร่วมกับคณะครุศาสตร์ ระยะยาวเสนอคุรุสภา — ไม่เคลมแทนการสอบครูผู้ช่วย |
| สอบออนไลน์กันโกงยังไง? | การสอบเป็น performance สด — เด็ก AI ถามไม่ซ้ำกันในแต่ละรอบ ลอกกันยากโดยธรรมชาติ + กล้องคุมสอบ ส่วนศูนย์สอบมีผู้คุมสอบ |
| เน็ตหลุดกลางคาบสอบ? | ระบบ checkpoint ให้ resume ต่อจากจุดเดิมได้ |
| ต้นทุน API แพงไหม? | ควบคุมด้วยการจำกัดความยาวคาบ + ใช้โมเดลเล็กสำหรับ persona และโมเดลใหญ่เฉพาะการประเมิน |
| ข้อมูล/ความถูกต้องของเนื้อหา? | ครูเป็นผู้กำหนดเนื้อหาและ learning objectives เอง ระบบวัด "การถ่ายทอด" ไม่ใช่ผู้ผลิตเนื้อหา |

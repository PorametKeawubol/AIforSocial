# รายงานผลการทดลอง Lab: KFC Intent Detection ด้วย 6 Intent

## 1. ขอบเขตการทดลอง

ใช้โมเดลเดิม `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` โดยไม่เปลี่ยนโมเดล การทดลองรองรับ 6 intent ได้แก่ `menu`, `promotion`, `location`, `greeting`, `order` และ `thanks` ส่วน `other` ใช้เป็นผลลัพธ์เมื่อคะแนนต่ำกว่า threshold

การประเมินรอบนี้แยกข้อความทดสอบออกจาก `INTENT_EXAMPLES` และไม่ใช้ข้อความเดิมแบบตรงตัว เพื่อไม่ให้ cosine similarity เท่ากับ `1.000` เพียงเพราะข้อความซ้ำกับข้อมูลฝึก ชุดทดสอบมี 42 ข้อความ หรือ 7 ข้อความต่อ intent

> หมายเหตุ: threshold `0.70` ถูกกำหนดไว้ก่อนการรันรายงานรอบนี้ แต่มีการทดลองข้อความกำกวมบางส่วนไปแล้ว จึงควรถือผลนี้เป็น baseline ที่ซื่อสัตย์ขึ้น ไม่ใช่ blind benchmark ที่สมบูรณ์

## 2. วิธีคำนวณ

สำหรับข้อความผู้ใช้ (q) ระบบจะหา cosine similarity กับตัวอย่างทุกข้อความในแต่ละ intent แล้วใช้คะแนนสูงสุดของ intent นั้น:

```text
score(intent) = max(cosine_similarity(query, example) for example in intent_examples)
```

จากนั้นเลือกคะแนนสูงสุด ถ้าต่ำกว่า `0.70` จะคืนค่า `other` ค่า Similarity ไม่ใช่ probability และไม่ควรตีความว่า `0.90` หมายถึงมั่นใจ 90%

## 5. กรณีที่ตรวจจับผิด

- `หิวมาก` เป็นความต้องการเกี่ยวกับเมนู แต่ระบบได้คะแนนสูงสุดไปทาง `order` ที่ `0.650` ซึ่งต่ำกว่า threshold จึงตอบ `other`
- `ช่วงนี้ KFC มีข้อเสนออะไร` มีคะแนน `order = 0.888` สูงกว่า `promotion = 0.871` เพราะคำถามพูดถึง KFC และข้อเสนอแบบกว้าง ๆ
- `ซื้อชุดไหนคุ้มสุด` และ `มีดีลพิเศษช่วงนี้ไหม` มีคะแนน promotion เพียง `0.520` และ `0.674` จึงถูกจัดเป็น `other`
- `จะซื้อไก่ต้องทำอย่างไร` ถูกทำนายเป็น `menu` เพราะคำว่า “ซื้อไก่” ใกล้กับตัวอย่าง menu มากกว่า order
- `สั่งผ่านมือถือได้ไหม` และ `ขอขั้นตอนการสั่งหน่อย` ยังไม่ผ่าน threshold แม้เป็น order จริง
- greeting แบบอ้อม ๆ เช่น `ขอเริ่มคุยด้วยนะ` และ `มีใครอยู่ไหม` ถูกจัดเป็น `other`

## 6. Boundary cases

ทดสอบข้อความที่อยู่นอก 6 intent แยกต่างหาก เพื่อดู false positive:

| ข้อความ | Intent จริง | Intent ที่ทำนาย | Similarity | ถูก/ผิด |

| เปิดร้านกี่โมง | other | other | 0.508 | ✓ |
| อยากสมัครสมาชิก | other | other | 0.518 | ✓ |
| ทำไมไก่แพง | other | other | 0.628 | ✓ |
| โอเค ได้เลย | other | greeting | 0.925 | ✗ |
| เข้าใจแล้วครับ | other | greeting | 0.821 | ✗ |
| **รวม** |  |  |  | **3/5** |

ระบบยังมี false positive กับประโยคยืนยันสั้น ๆ ที่ไม่มีคำทักทายโดยตรง จึงควรเพิ่ม `other` examples และใช้ margin ระหว่างอันดับหนึ่งกับอันดับสองในการตัดสินใจ

## 7. ข้อเสนอปรับปรุง

1. เพิ่มข้อความจริงจากผู้ใช้ โดยเฉพาะ `promotion` และ `order` ที่มี accuracy ต่ำสุด 57.14%
2. แยก train/validation/test ให้ชัดเจน และปรับ threshold จาก validation เท่านั้น
3. เพิ่ม `other` examples เช่น สอบถามเวลาเปิดร้าน สมัครสมาชิก หรือแสดงความคิดเห็นเรื่องราคา
4. ทดลองใช้ centroid หรือ top-k average แทน `max` เพื่อลดการพึ่งพาตัวอย่างเดียว
5. รายงาน confusion matrix และ macro-F1 ควบคู่กับ accuracy

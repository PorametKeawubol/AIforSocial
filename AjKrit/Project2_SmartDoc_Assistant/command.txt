SmartDoc Assistant — คำสั่งรัน RAG + LINE UX + Chat History

รันใช้งานประจำ: Terminal 1 เปิด Ollama → Terminal 2 เปิด webhook → Terminal 3 เปิด tunnel
ไม่ต้อง build index หรือติดตั้ง Rich Menu ใหม่ทุกครั้ง
ไฟล์นี้เป็นคู่มือ ให้คัดลอกเฉพาะคำสั่ง ไม่ใช่สคริปต์สำหรับ bash command.txt

ค่าปัจจุบัน: Qwen qwen3.5:9b + BGE-M3 + BAAI/bge-reranker-v2-m3 + FAISS/BM25
Rerank ค่าเริ่มต้น 6 chunks; ถ้า top_k เกิน 6 จะประเมินอย่างน้อยเท่ากับ top_k
ไม่ต้องเพิ่ม RERANK_K ใน .env — ตอนนี้ค่าอยู่ใน HybridRetriever.search()
หลังลด rerank ไม่ต้อง rebuild index; ต้อง restart webhook เพื่อโหลดโค้ดใหม่
LINE RAG ใช้ข้อความรับคำถามจาก LINE_ACK_TEXT ใน .env ทั้งแชตส่วนตัวและกลุ่ม
ปิด loading และข้อความแจ้งรอเกิน 30 วินาทีแล้ว; ตอบเสร็จส่งผ่าน Push ตามเดิม
ทักทาย/เมนูตอบทันที; ล้างประวัติส่งข้อความยืนยันโดยไม่ส่ง acknowledgement ซ้ำ

1. เข้า project — ใช้ absolute path นี้ในแต่ละ terminal เพื่อไม่เจอปัญหา cd ซ้ำ:
cd /home/porametk/Desktop/AIforSocial/AIforSocial/AjKrit/Project2_SmartDoc_Assistant

ติดตั้ง dependencies เฉพาะเมื่อจำเป็น:
.venv/bin/pip install -r requirements.txt
.venv/bin/pip check

ถ้ายังไม่มี .venv ให้สร้างก่อน:
python3 -m venv .venv
จากนั้นติดตั้ง dependencies ตามคำสั่งข้างบน
ตรวจว่า .env มี CHANNEL_SECRET และ CHANNEL_ACCESS_TOKEN แล้ว ห้ามนำค่าจริงไปเผยแพร่

2. Build index และทดสอบ — index ปัจจุบัน build แล้ว รันใหม่เมื่อเปลี่ยน PDF/chunking:
.venv/bin/python build_index.py \
  --chunk-size 900 \
  --overlap 120 \
  --parent-size 2400

.venv/bin/python -m unittest discover -s tests -p 'test*.py' -v

3. Terminal 1: เปิด Ollama — เปิดค้างไว้:
ollama serve
ถ้า Ollama ทำงานเป็น service อยู่แล้ว ไม่ต้องเปิดซ้ำ
ตรวจว่า Ollama พร้อม และดูโมเดลที่มี (จาก terminal อีกอัน):
curl http://127.0.0.1:11434/api/tags
ollama list

ดาวน์โหลดเฉพาะโมเดลที่ยังไม่มี — เลือกตัวที่จะใช้:
ollama pull qwen3.5:9b
# ทางเลือกสำหรับทดสอบ offline ไม่จำเป็นสำหรับ production
ollama pull hf.co/unsloth/Qwen3.8-27B-GGUF:UD-Q4_K_M
คำสั่งดาวน์โหลดโมเดลต้องมีอินเทอร์เน็ตและพื้นที่ดิสก์เพียงพอ

4. Terminal ทดสอบ: ทดลองถาม (CLI แต่ละคำสั่งเป็นคำถามเดี่ยว ไม่เก็บ chat history)
# ค้นเอกสารอย่างเดียว
.venv/bin/python cli.py "เพื่อนหายตัวไปทำไง" --retrieve-only --json

# ตอบด้วยโมเดล production ตาม .env ซึ่งตอนนี้เป็น qwen3.5:9b
.venv/bin/python cli.py "เพื่อนหายตัวไปทำไง"

# ทดลอง 9B
OLLAMA_MODEL=qwen3.5:9b \
  .venv/bin/python cli.py "เพื่อนหายตัวไปทำไง"

6. เปิด LINE webhook — เลือกแบบ service หรือแบบ terminal อย่างใดอย่างหนึ่ง:
# ตอนนี้ webhook รันเป็น transient user-service smartdoc-webhook อยู่ ไม่ต้องเปิด uvicorn ซ้ำ
# หลังแก้ .env ให้ใช้ restart; ดู log ด้วย journalctl; ไม่ได้ตั้งให้เปิดอัตโนมัติหลังบูต
systemctl --user status smartdoc-webhook.service --no-pager
systemctl --user restart smartdoc-webhook.service
journalctl --user -u smartdoc-webhook.service -n 50 --no-pager
# ถ้าจะกลับไปรันแบบ terminal ตามคำสั่งข้างล่าง ให้หยุด service ก่อน
systemctl --user stop smartdoc-webhook.service

# เปิด user-service ใหม่หลังหยุด หรือหลัง reboot เมื่อ unit เดิมหายไป
# รันจาก directory project ตามข้อ 1; ห้ามเปิดซ้ำหาก port 8000 ถูกใช้อยู่
systemd-run --user --unit=smartdoc-webhook --collect \
  --working-directory=/home/porametk/Desktop/AIforSocial/AIforSocial/AjKrit/Project2_SmartDoc_Assistant \
  --property=Restart=on-failure --property=RestartSec=3 \
  /home/porametk/Desktop/AIforSocial/AIforSocial/AjKrit/Project2_SmartDoc_Assistant/.venv/bin/uvicorn \
  app:app --host 127.0.0.1 --port 8000
เป็น transient service: ไม่เปิดเองหลัง reboot และ unit ถูกเก็บกวาดเมื่อหยุด
restart ใช้เมื่อ unit ยังอยู่; หากขึ้น Unit not found ให้เปิดใหม่ด้วย systemd-run

# ทางเลือกแบบ terminal: หยุด service ก่อน แล้วเลือกคำสั่ง uvicorn ด้านล่าง

# ใช้โมเดลตาม OLLAMA_MODEL ใน .env
.venv/bin/uvicorn app:app --host 127.0.0.1 --port 8000

# หรือทดลอง 27B ชั่วคราว โดยไม่เปลี่ยน .env
OLLAMA_MODEL=hf.co/unsloth/Qwen3.8-27B-GGUF:UD-Q4_K_M \
  .venv/bin/uvicorn app:app --host 127.0.0.1 --port 8000

ปรับ history ได้ใน .env:
HISTORY_MAX_TURNS=4
HISTORY_TTL_SECONDS=86400
หลังแก้ .env หรือโค้ด: ถ้าใช้ service ให้ restart; ถ้าใช้ terminal ให้ Ctrl+C แล้วรันใหม่
ไม่ต้องเปิด webhook สองตัวบน port 8000 พร้อมกัน

สคริปต์อ่าน assets/richmenu_thaipol.png และแปลงรูปสำหรับอัปโหลดโดยไม่แก้ไฟล์ต้นฉบับ

หลังเปลี่ยนโค้ด ให้รีสตาร์ต webhook ตามรูปแบบที่เลือก แล้วเปิดแชต LINE ใหม่
เลือกหมวดเพื่อดู Flex Carousel หรือพิมพ์คำถามได้เลย
กด Quick Reply หรือถามต่อ เช่น ต้องเตรียมอะไร / ไปที่ไหน
พิมพ์ ล้างประวัติ เพื่อเริ่มเรื่องใหม่

เก็บใน artifacts/chat_history.sqlite3 แยกผู้ใช้และห้องแชต; ไม่ต้องมี Knowledge Graph
ข้อมูลที่หมดอายุถูกลบเมื่อมีการเข้าถึง history ไม่ใช่ background timer
ไฟล์ history มีข้อความส่วนตัว ห้ามนำไปแนบส่งงานหรือเผยแพร่
การกดเลือกหมวดยังไม่เปลี่ยนบริบท ต้องเลือกหัวข้อย่อยหรือถามเรื่องใหม่ก่อน

11. เปรียบเทียบโมเดล — ไม่เปลี่ยน .env หรือ index ของ LINE:
# ดาวน์โหลด LLM เพิ่มจาก Mistral (ครั้งแรกเท่านั้น)
ollama pull ministral-3:8b

# Embedding 3 ตัว: BGE-M3 / multilingual-e5-large / Qwen3-Embedding-0.6B
# CPU FP32, 512 tokens; dense กับ hybrid RRF ไม่มี reranker; 3 รอบ latency ต่อคำถาม
.venv/bin/python benchmark_models.py --stage embeddings

# LLM 3 ตัว: Qwen 27B / Qwen 9B / Ministral 3 8B
# ลำดับรัน: Ministral 8B → Qwen 9B → Qwen 27B
# เปิด Ollama ก่อน ใช้ frozen context เดียวกัน + SBERT scorer เดียวกัน + BERTScore
# ใช้เวลานาน โดยเฉพาะ 27B; งดถาม LINE ระหว่างรันเพื่อไม่รบกวนเวลาแฝง
.venv/bin/python benchmark_models.py --stage llms

# เปลี่ยน comparator จาก Gemma เป็น Ministral โดยใช้ผล Qwen และหลักฐานเดิม:
# ย้าย summary ของ Gemma ไป archived_llms; ไฟล์คำตอบเก่าไม่ถูกลบ
.venv/bin/python benchmark_models.py --stage llms \
  --llm-models ministral-3:8b --archive-llm gemma3:4b

# หรือรันทั้งสองขั้นตอนต่อกัน
.venv/bin/python benchmark_models.py --stage all

# หากหยุดกลางทาง รันคำสั่งเดิมซ้ำได้ จะอ่าน checkpoint และทำต่อ
# หากเปลี่ยนชุดคำถามหรือพารามิเตอร์ ให้แยก output ใหม่ เช่น
.venv/bin/python benchmark_models.py --stage all --out artifacts/model_benchmark_v2

# สำคัญหลังเปลี่ยน rerank: model_benchmark เดิมใช้ frozen_contexts ของรอบเก่า
# รันคำสั่งเดิมจะใช้ checkpoint/คะแนนเดิม ไม่ใช่ประเมิน pipeline ใหม่
# ถ้าจะสร้าง context และผลเปรียบเทียบใหม่ภายใต้ rerank 6 ให้ใช้ output แยก:
.venv/bin/python benchmark_models.py --stage llms \
  --out artifacts/model_benchmark_rerank6
คำสั่งนี้รัน LLM ทั้ง 3 ตัวรวม 27B จึงใช้เวลานาน; ถ้าต้องการตรวจเฉพาะ production
ให้ใช้ full evaluation 9B ในข้อ 5 แทน

ผลลัพธ์: artifacts/model_benchmark/comparison.md, comparison.json, embeddings.csv, llms.csv
rows.json และ *_answers.json เก็บผลรายคำถาม; frozen_contexts.json เก็บหลักฐานร่วม
Recall@k แบบ section เท่ากับ Hit@k เพราะชุดคำถามมี 1 target_section ต่อข้อ
Retrieval F1 ไม่ใช่ BERTScore F1; cosine ต่างโมเดลมีสเกลต่างกัน อย่าจัดอันดับด้วย cosine อย่างเดียว
p95 ของ LLM เป็นผล 18 คำถาม 1 รอบ ยังเป็นผลเบื้องต้น ไม่ใช่ SLA

## หลักการเลือกความสัมพันธ์

1. ใช้กราฟเฉพาะเนื้อหาการเกษตร: `Crop → HAS_DISEASE → Disease → CAUSED_BY / HAS_SYMPTOM / MANAGED_BY` และขยายชนิดสำหรับดิน วัสดุ ชีวภัณฑ์ พาหะ ฤดู และสภาพแวดล้อม
2. แยกโรคตามพืชและเชื้อ เช่น โรคใบด่าง CVMV/PVY/CMV/TEV ของพริก และโรครากเน่าโคนเน่าของพริกกับทุเรียน ไม่รวมเพียงเพราะชื่อโรคคล้ายกัน
3. ใช้โหนดกลางร่วมกันเมื่อเป็นสิ่งเดียวกัน เช่น เพลี้ยอ่อน การปลูกพืชหมุนเวียน และชีวภัณฑ์ รวมรูปสะกด `บาซิลลัส ซับติลิส` ไว้เป็น alias ของ `บาซิลลัส ซับทีลิส`
4. แยก `Biocontrol` ออกจาก `Pathogen` จึงไม่จัดไตรโคเดอร์มาที่เอกสารใช้ควบคุมโรคเป็นเชื้อสาเหตุ
5. ใช้ `CO_OCCURS_WITH` เฉพาะกรณีที่เอกสารบอกว่าพบร่วมกัน เช่น มอดเจาะลำต้นกับโรคทุเรียน ไม่เปลี่ยนเป็นความสัมพันธ์เชิงสาเหตุ
6. สูตรน้ำส้มควันไม้แยกตามการใช้งานและอัตราส่วน ไม่รวมอัตราต่างกันเป็นข้อแนะนำเดียว
7. เลขหน้าใช้ลำดับ PDF เริ่มที่ 1 เก็บหลักฐานเป็นข้อความเต็มหน้าพร้อมหน้าบริบทสำหรับเนื้อหาที่ต่อหน้า ตรวจภาพหน้า 33 ประกอบเพื่อแยกวิธีจัดการ TEV กับใบหงิกเหลืองซึ่งลำดับข้อความสกัดสลับกัน

`MANAGED_BY` และทุกความสัมพันธ์เชิงเนื้อหาหมายถึง **สิ่งที่คู่มือปี 2562 รายงาน** (`assertion=reported_in_source`) ไม่ใช่การรับรองว่าทุกวิธีได้ผลทางวิชาการ ข้อมูลสารเคมีและภูมิปัญญาไม่ได้ตรวจสถานะการอนุญาตหรือหลักฐานประสิทธิผลปัจจุบัน กราฟชุดนี้จึงเป็นการนำเสนอเนื้อหาเอกสาร

## นำเข้า Neo4j

นำเข้าและอ่านกลับจาก Neo4j จริงแล้ว: 266 โหนด / 879 ความสัมพันธ์ ตรงกับข้อมูลครบชุด ผลตรวจและภาพ Browser อยู่ใน `neo4j_native/`.

### วิธีที่ 1: Cypher Shell

เปิดฐานข้อมูลของคุณ แล้วจากโฟลเดอร์นี้เรียก:

```bash
cypher-shell -a bolt://localhost:7687 -u neo4j -f import.cypher
```

ให้โปรแกรมถามรหัสผ่าน หรือใช้ environment ของคุณ หาก Neo4j ใช้พอร์ตอื่นให้ปรับ URI คำสั่งใช้ `MERGE` พร้อม ID คงที่และ label `PlantGuide2019Reviewed` เพื่อแยกชุดข้อมูล ไม่ลบกราฟเดิม การนำเข้าด้วย Cypher Shell มีหลาย statement จึงอาจค้างบางส่วนหากหยุดกลางทาง และสามารถรันซ้ำเพื่อเติมส่วนที่เหลือได้

### วิธีที่ 2: Python driver

ติดตั้งแพ็กเกจ `neo4j` ใน virtual environment ตั้ง `NEO4J_URI`, `NEO4J_USERNAME`, `NEO4J_PASSWORD` และถ้าจำเป็น `NEO4J_DATABASE` แล้วรัน:

```bash
python import_neo4j.py
```

วิธีนี้นำเข้าโหนดและความสัมพันธ์ใน transaction เดียวหลังสร้าง constraint และตรวจจำนวนที่อ่านกลับจากฐานข้อมูล ข้อมูลหลักฐานเต็มหน้าเก็บใน `Page.text`; ความสัมพันธ์เก็บ `pages` สำหรับค้นกลับ จึงไม่ทำซ้ำข้อความทั้งหน้าในทุกเส้นของฐานข้อมูล

Syntax ที่ใช้เป็นรูปแบบ constraint ของ Neo4j 5 และ Cypher มาตรฐาน และยืนยันการนำเข้าผ่าน Python driver กับ Neo4j ในเครื่องแล้ว: [Neo4j constraint syntax](https://neo4j.com/docs/cypher-manual/5/constraints/syntax/).

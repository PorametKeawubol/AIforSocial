การประเมินโปรเจกต์พัฒนาระบบเว็บร้านค้าที่ประกอบด้วย Web Scraping, NLP และ Random Top 5 Carousel สามารถแบ่งเกณฑ์ประเมิน (Rubric Score) ออกเป็น 5 ด้านหลัก รวม 100 คะแนน ดังนี้:

ด้านการประเมิน	น้ำหนัก	ดีมาก (4–5 คะแนน)	พอใช้ (2–3 คะแนน)	ต้องปรับปรุง (0–1 คะแนน)
1. Web Scraping & Data Pipeline	25%	ดึงข้อมูลได้ครบถ้วน จัดทำ Data Cleaning สกัด Attributes (ราคา, ชื่อ, รูป) ชัดเจน และเว้นระยะการดึงข้อมูลอย่างเหมาะสม	ดึงข้อมูลได้เป็นส่วนใหญ่ ข้อมูลบางส่วนขาดหาย หรือจัดเก็บลง Database โดยยังมี Noise ติดมา	ดึงข้อมูลล้มเหลวบ่อย โครงสร้างข้อมูลไม่สมบูรณ์ หรือไม่มีการจัดการ Error เมื่อเว็บต้นทางเปลี่ยน
2. NLP Command Processing	25%	จับ Intent และ Entity ของคำสั่งได้แม่นยำ (>85%) รองรับคำสั่งซับซ้อน ภาษาพูด และคำพิมพ์ผิดได้ดี	ตีความคำสั่งพื้นฐานได้ แต่สับสนเมื่อเจอประโยคซับซ้อน หรือคำสั่งที่มีหลายเงื่อนไขพร้อมกัน	ไม่สามารถวิเคราะห์ Intent ของผู้ใช้ได้ หรือส่งผลลัพธ์ไม่ตรงกับคำสั่งอย่างรุนแรง
3. Top 5 Carousel Logic & Randomization	20%	กรองสินค้ากลุ่ม Top 5 ตรงตามเงื่อนไข อัลกอริทึมสุ่มกระจายตัวได้ดี ไม่ซ้ำซ้อน และ UI Carousel สไลด์สมูท	คัดเลือกสินค้าได้ตรง แต่ระบบสุ่มยังไม่มีประสิทธิภาพ (สุ่มได้สินค้าเดิมบ่อย) หรือแสดงผลหน่วง	แสดงผลไม่ครบ 5 รายการ ลอจิกการสุ่มไม่ทำงาน หรือ Carousel ค้างไม่สามารถเลื่อนได้
4. LINE Interface & Chat UX	15%	ออกแบบ Flex Message/Carousel สวยงาม สัดส่วนภาพพอดี อ่านง่าย ปุ่ม Action (เช่น สั่งซื้อ/ดูรายละเอียด) ใช้งานสะดวก และมี Quick Reply หรือ Rich Menu ช่วยให้ผู้ใช้ส่งคำสั่ง NLP ได้ง่าย	แสดงผล Carousel บน LINE ได้ แต่ข้อความถูกตัด (Truncate) เนื่องจากยาวเกินกำหนด รูปภาพสัดส่วนไม่สมดุล หรือปุ่ม Action กดยาก/สร้างความสับสน	โครงสร้าง Flex Message ผิดพลาด (JSON Error) จนไม่แสดงผล รูปภาพไม่โหลด หรือรูปแบบการโต้ตอบในห้องแชทสับสนจนผู้ใช้ใช้งานต่อไม่ได้
5. Code Quality & Performance	15%	เขียนโค้ดเป็น Modular/Clean Code มี Error Handling ครอบคลุม และประมวลผลคำสั่ง NLP + แสดงผลได้รวดเร็ว	โค้ดทำงานได้ตามเป้าหมาย แต่โครงสร้างซับซ้อน ประมวลผลคำสั่ง NLP หรือโหลด Carousel ค่อนข้างช้า	โค้ดอ่านยาก ไม่มี Error Handling ระบบล่มง่ายทันทีเมื่อเจอ Data Input ที่ไม่คาดคิด
จุดเน้นย้ำในการทดสอบ (Key Checkpoints)

Scraping Robustness: ทดสอบว่าระบบจัดการกับโครงสร้าง HTML ที่เปลี่ยนไป หรือการดึงข้อมูลที่ไม่สมบูรณ์ (Missing values) ได้โดยไม่ทำให้เว็บ crash
NLP Latency & Edge Cases: วัด Response Time ตั้งแต่ผู้ใช้พิมพ์คำสั่งจนถึงการดึงผลลัพธ์ขึ้นจอ (ควรต่ำกว่า 1.5-2 วินาที) พร้อมทดสอบคำสั่งรูปแบบแปลกๆ
Randomization Fairness: อัลกอริทึมการสุ่มในกลุ่ม Top 5 ต้องไม่ติด Loop ดึงสินค้าชิ้นเดิมขึ้นมาแสดงบ่อยเกินไปในการรีเฟรชแต่ละครั้ง
